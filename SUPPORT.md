# Support

Pick the right channel and you will get a useful answer faster.

| You want to… | Go here |
|---|---|
| Ask how something works | **Discussions → Q&A** on the relevant repository |
| Report a bug you can reproduce | **Issues → Bug report** |
| Propose a feature | **Issues → Feature request** |
| Report a vulnerability | [SECURITY.md](SECURITY.md) — never a public issue |
| Fix something yourself | [CONTRIBUTING.md](CONTRIBUTING.md) |

## Before you ask

Most questions are answered by three things:

1. The repository `README.md`, including the collapsed sections.
2. `<command> --help` on the tool itself.
3. Re-running with verbose output. Nearly every tool here takes `-v` or
   `--verbose`, and it usually says exactly what went wrong.

## Making a question answerable

Include the version (`<command> version`), your operating system, the exact
command you ran, and the complete output — not a paraphrase of the error. Paste
text, not screenshots: text is searchable, so the next person with your problem
finds your thread.

## What is not supported

- Private one-to-one help. Questions and answers stay public so they compound.
- Running these tools on end-of-life operating systems or unsupported Go versions.
- Configuration of third-party services these tools talk to. We will point you
  at the right documentation, but their setup is theirs.

## Response times

This is unpaid, best-effort work maintained in spare hours. Bugs with clear
reproduction steps get looked at first. Security reports get looked at
immediately. Everything else gets there when it gets there — a nudge after a
week is welcome, not rude.
